这套规范想解决的几件事

  1. 分区代替平铺。每个弹窗拆成 3–5 个 .m-section，用 1px 分隔线而不是大留白区分；分区标题是 mono 小字眉标，不去抢字段的注意力。
  2. 短字段并排，长字段独占。.m-grid + --m-cols 控制列数；URL / Key / 列表类字段用 .m-full 占整行，弹窗宽度因此可以收窄（渠道 760 → 720）。
  3. 数量与状态常驻标题行。"2/3 启用""18 个模型""已选 3 个" 这类计数放在分区标题右侧，列表再长也不用翻到底去找。
  4. 高级项折叠但可见。ModalAdvanced 折叠区带"已自定义 N 项"徽标：没改过显示灰底"使用默认值"，改过显示琥珀色计数，不会因为藏起来就被忘掉。
  5. 确认弹窗同构。删除 / 重置 / 刷新这类操作全部走 useConfirm()，形态固定为"说明 → 对象 → 要点"三段；名称用等宽字体标出避免认错，要点回答"为什么要谨慎"。危险程度只由确认按钮颜色区分，图标一律用警示三角——叉号读起来像"已经出错了"。执行期间按钮自动转圈，防重复提交。
